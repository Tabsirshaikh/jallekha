# `feat/t1-dedup` — `T1`

- **Owner / date:** P3, 2026-10-02.
- **Purpose:** Build the F13 duplicate engine: link repeat complaints about the same incident, keep the duplicate rate per area as a reporting-activity signal, and prepare the Chicago calibration.
- **What we found:** The rule is fully specified in `docs/JALLEKHA_FINAL_SOLUTION.md` F13: same household first; otherwise 100 m and a per-category window (48 h no-water / tanker-missed / dirty water, 7 days leak / other). The D13 Chicago extract is not in the repo (S2 review: "frozen extract not found"), and the live Chicago dataset changes several times a day, so the old 31,098-row snapshot cannot be re-pulled exactly. Calibration therefore waits for P1's logged fresh pull. A five-point fixture showed that chained duplicates link through the middle report (C matches B, B matches A), so the cluster root is resolved with union-find.
- **What we changed:** `backend/app/config/trust.py`: F13 radius, category windows and text-similarity settings (off by default), each with its source. `backend/app/services/dedup.py` (pure): `haversine_m`, `find_parent` (household → location + time; only earlier, same-category complaints; inclusive radius and window), `link_duplicates` (time-ordered, grid index, union-find to the cluster root), `duplicate_rate_by_area` (per area and UTC month/week, with `duplicate_rate_basis`), optional LaBSE text similarity that only records a score and falls back cleanly when the `ml` extra is missing. `backend/app/models/complaint.py` and `duplicate_link.py` (one table each; one link per child). `scripts/trust/calibrate_dedup.py`: reproduces the F13 / section 7 measures (p95 child-parent distance, p90 hours per type, linked share for 100 m / 48 h and 300 m / 7 d) and writes `data/derived/dedup_calibration.csv` (DERIVED), next to the solution document's numbers for comparison only.
- **Validation:** Tests written first; before the service existed the test file failed at import (`app.services.dedup` missing). `python tasks.py test`: 105 backend tests (73 before + 32 new: 24 rule, 6 calibration script, 2 models), 1 frontend test, all P1 verifiers, exit 0. `python tasks.py lint` exit 0. `verify_main_integration.py` and `verify_p1_r_p1.py` pass. - **Known limitations:** No calibration numbers yet (needs D13). Text similarity is untested on Indian data and off by default; it never decides a merge. Monthly/weekly periods are in UTC. Chicago timestamps are local without zone, so pairs across a daylight-saving change can be off by one hour. The Chicago SR types that correspond to "no-water" and "leak" in F13 are not mapped yet; the script reports per SR type and leaves that comparison to the reviewer.
