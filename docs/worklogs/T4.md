## `feat/t4-ledger-wiring` — `T4` follow-up (ledger wiring)

- **Owner / date:** P3, 2026-10-02.
- **Purpose:** Log intake events to T6's stored ledger now that #35 is merged.
- **What we found:** The three intake event types did not exist; adding them breaks T4's test `test_no_ledger_entries_while_no_intake_event_type_exists`, whose premise is that they are absent. A ledger write happens after the report is saved, so a failing ledger (for example no `LEDGER_HMAC_KEY`) must not lose the report.
- **What we changed:** `services/ledger.py`: `complaint_received`, `complaint_merged`, `complaint_marked_spam` in `EVENT_TYPES` (own commit). The one T4 test adapted in its own commit (types removed for that test only; its purpose, that intake writes nothing without the types, is kept). `services/intake_pipeline.py`: `default_service` passes `ledger_store.get_ledger()`; results carry `ledger_seq`; a ledger failure is logged, the report kept. `models/intake_item.py`: `ledger_missing` marker, set when an entry is expected and cleared once written; `IntakeService.intake_ids_missing_ledger()` lists such items. Tests `backend/tests/services/test_intake_ledger.py`.
- **Validation:** Tests written first (they failed before the wiring). 8 new tests: event types exist; created, merged and spam items write entries and the stored chain verifies; duplicates and invalid items write nothing; no payload holds a phone number, name, text, audio or household id (SMS, missed call, field worker, voice, spam); a ledger failure keeps the report and is logged; the default service writes to the stored ledger; missing entries are marked and can be listed; no marker without a ledger. `python tasks.py test` exit 0: 421 backend passed, 1 frontend test, all P1 verifiers. `python tasks.py lint` exit 0.
- **Known limitations:** No automatic retry for marked items yet. The new column needs a fresh database or a manual column add (no migrations; `create_all` does not alter tables).
- **Handoff / next step:** T5 and T7 log through `ledger_store.record` the same way. A retry job for `ledger_missing` items can be added later.
